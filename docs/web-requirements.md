# pic2gray4px Web 要件定義書

## 1. 目的と位置づけ

pic2gray4px の Web 版。写真をブラウザ上で 1-bit グレースケール PNG に変換し、
感熱プリンタ（T02 / M02S 等）や小型 E-ink ディスプレイですぐ使える形にする。

- 変換アルゴリズムの正本は、従来どおりこのリポジトリの Rust ライブラリ
  （`src/lib.rs` / `src/autotune.rs` / `src/optimizer.rs`）とする。複製を作らない。
- CLI は残す。CLI はバッチ・自動化の顔、Web は「スマホの写真をその場で変換して刷る」顔。
  両者は同じライブラリの別バインディングである。
- Web 版は完全クライアントサイドで動作する。画像をサーバへ送らない。
- 公開先は GitHub Pages： https://tanep3.github.io/pic2gray4px/

## 2. 使い方の流れ（エンドツーエンド）

1. ページを開く。
2. 写真を選ぶ（ファイル選択ボタン、または画面へのドラッグ＆ドロップ）。
3. 出力サイズを選ぶ（初期値は原画サイズ。プリセットかカスタム幅）。
4. 自動で変換が走り、原画と変換結果が並んで表示される。
   実際に適用された contrast / unsharp の値も表示される。
5. 「共有」から Phomemo アプリへ送って印刷、または PNG を保存する。

例：スマホ写真 4032×3024 をプリセット「384（T02等）」で変換すると、
縦横比を保った 384×288 の 1-bit PNG が得られる。

## 3. 機能要件

### 3.1 入力

1. ファイル選択（ボタン／タップ）とドラッグ＆ドロップの両方に対応する。
2. 他のアプリからの共有も受け付ける（Web Share Target API）。
   写真アプリ等の共有メニューに本アプリが並び、選ぶと画像がそのまま変換フローに入る。
   前提は PWA としてインストール済みであることと Android / Chrome 系であること。
   iOS は共有ターゲットに未対応のため、その場合はファイル選択／ドラッグ＆ドロップを使う
   （制限として明記する）。
   - 受信仕様：マニフェストに `share_target` を設定し、画像ファイルは
     POST / multipart/form-data で受け取る。
   - GitHub Pages は POST の受け口にならないため、共有 POST は Service Worker が
     受信し、ブラウザ内で一時保持して Web アプリに引き渡す。ページ遷移で
     データを失わないこと。
   - 画像は外部サーバーへ送信せず、処理後に破棄する（完全クライアントサイドと整合）。
3. クリップボードからの貼り付けにも対応する。共有ターゲットが使えない iOS での
   代替入力経路とする。経路は paste イベントの1本だけとする
   （Voice2QR v1.2.2 で確定した形に準拠、2026-11-16）。
   - PC：Ctrl+V / Cmd+V（paste イベント）で受け取る。
   - スマホ：編集可能な「貼り付け受け箱」をタップし、OS の呼び出しメニューの
     「ペースト」で取り込む。ページ側から能動的に読み取ることはできない。
   - Async Clipboard API（`navigator.clipboard.read()`）は使わない。その画像の
     表面は実質 PNG のみで、他アプリが JPEG で置いたコピーは到達しない
     （iPad で X からコピーした画像で実測）。paste イベントの従来経路は
     JPEG 等も通す。
4. 対応形式はブラウザがデコードできる画像（PNG / JPEG / WebP 等）。
5. EXIF の向きを反映する（スマホ写真が横倒しにならないこと）。
6. 透過画像は白地へ合成する（CLI と同じ）。
7. 読み込んだ画像は端末の外へ送らない。再読み込みで別の画像に差し替えられる。

### 3.2 出力サイズ

1. 幅の初期値は **原画のピクセル幅**（＝リサイズなし変換）。
2. プリセット（いずれも幅指定）：
   - 384（T02等・200dpi 級）
   - 576（M02S等・300dpi 級）
   - 250（E-ink 2.13" パネルの幅）
3. カスタム幅：任意の正の整数を直接指定できる。高さは縦横比を保って決まる
   （CLI の `--width` と同じ規則）。
4. 高さの指定は設けない。CLI に `--height` が無い以上、Web だけの特別扱いはしない。
   E-ink も幅 250 のプリセットとして扱い、高さは原寸比のままとする
   （パネルへの収め方は表示側の仕事）。
5. 奇数寸法は CLI と同じく右・下へ白画素を補って偶数にする。
6. **大きな画像の上限（Web のみ）**：変換の作業メモリは画素数に比例して増え、
   原画サイズのままではスマホのブラウザがメモリ不足で落ちる（実測：12MP で
   ピーク約1GB、24MP で約2GB。2026-11-16 に iPhone で障害報告あり）。
   出力画素数が上限（400万画素、`web/src/client.ts` の
   `MAX_CONVERSION_PIXELS`）を超える場合は、変換可能なサイズまで縮小して
   変換し、結果表示にその旨を明記する。落ちるより縮小された結果を出す。
   CLI は対象外（PC のメモリ前提）。

### 3.3 変換

1. 既定は全自動：contrast 自動、unsharp 自動、セル拡散オン、passes 10
   （CLI のデフォルトと一致）。
2. 結果には実際に適用された値を表示する（contrast / unsharp の実値、
   拡散のオン・オフ、出力寸法）。CLI が標準出力に出す情報と同じもの。
3. サイズ変更や設定変更のたびに再変換する。変換中は処理中であることが分かる表示にする
   （大きな原画では時間がかかるため）。
4. 変換は Web Worker で実行する。メインスレッドを塞がず、変換中も進捗表示や
   UI 操作を受け付けられること。
5. 変換要求ごとに世代番号を振り、画面へ反映するのは最新世代の結果だけとする。
   途中でサイズや設定を変えた場合、先行する古い変換が後から終わっても
   その結果で上書きしない。

### 3.4 上級者設定（畳んで表示）

通常は閉じておき、開いたときだけ次の手動調整ができる。意味と範囲は CLI と一致させる。

| Web の設定 | CLI | 範囲 | 既定 |
| --- | --- | --- | --- |
| contrast | `--contrast auto\|off\|C` | 自動／オフ／0〜3 | 自動 |
| unsharp | `--unsharp auto\|off\|A` | 自動／オフ／0〜2 | 自動 |
| セル拡散 | `--no-diffusion` | オン／オフ | オン |
| passes | `--passes N` | 0〜10 | 10 |

### 3.5 プレビュー

1. 原画と変換結果を並べて表示する（モバイルでは縦積み）。
2. 変換結果はドットが潰れない表示（`image-rendering: pixelated`）とし、
   タップ／クリックで拡大表示できる。

### 3.6 出力

1. PNG 保存：1-bit グレースケール PNG（CLI の出力と同じ形式）。
2. 共有：Web Share API で OS の共有シートを出し、Phomemo アプリ等へ渡せる。
   共有が使えない環境では保存にフォールバックする。
3. PC ではブラウザ印刷も可能とする（MiniMapPrint と同じ印刷 CSS の作法）。

## 4. コア契約

ブラウザと Rust コアの境界は、CLI と Web で同じ結果を出すことを優先して引く。
Canvas のリサイズはブラウザ依存の補間であり Rust の Lanczos3 と一致する保証がなく、
Canvas の PNG 出力では 1-bit グレースケールを指定できないため、
結果を決める処理はすべてコア（既存 Rust ライブラリ）に置く。

- ブラウザ側の仕事：画像デコード、EXIF 向きの反映、RGBA の取り出しまで。
  コア側に画像デコーダを持たない。
- コア側の仕事：Lanczos3 リサイズ（縦横比維持、CLI の `image` クレートと同じ処理）、
  変換（2×2 セルの白点数決定、拡散、配置最適化、自動調整）、
  1-bit PNG のエンコード（CLI の `png` クレートと同じ処理）。
- コアの公開関数は 2 つ：
  - `convert_rgba(rgba, width, height, options)` — `options` は目標幅
    （null = リサイズなし）、contrast / unsharp（null = 自動）、passes、diffusion。
    戻り値は 1-bit パック済みピクセル、出力寸法、実際に使われた contrast / unsharp の値。
  - `encode_1bit_png(width, height, bits)` — CLI と共通の 1-bit PNG エンコード。
    WASM からも呼べること。
- テスト条件：**同一の RGBA 入力に対する変換結果（ピクセル列と PNG）が
  CLI と Web で一致すること**を、コアのテストで担保する。
  ブラウザのデコーダと Rust のデコーダの差（色変換等）は境界の外に残るため、
  一致の保証範囲は「RGBA が確定した後」とする。
- なお、リサイズをコア側に置くため、コアへ渡る RGBA は原寸になる
  （12MP で約 49MB）。この転送と変換は §3.3 の Web Worker の中で行うこと。

## 5. 非機能要件

- 完全クライアントサイド。通信は静的ファイルの取得のみ。
- UI 言語は端末の言語を初期値とし、日本語／英語を切り替えられる（Voice2QR と同じ）。
- PWA とする：ホーム画面に追加でき、単独ウィンドウのアプリとして起動する
  （マニフェスト＋アイコン＋Service Worker）。Service Worker のキャッシュ接頭辞は
  `pic2gray4px-` とし、他アプリのキャッシュを消さない（同一オリジン共有の教訓）。
- レスポンシブデザイン：スマホ（縦積み）から PC（横並び）まで崩れない。
- デザインは **究極にエモく**。Voice2QR と同じ方向性（ゆめかわ／エモ）で、
  第一印象で「使いたい」と思えることを機能と同じ重さの要件とする。
- バージョンは画面に刻印し、`version.json` を発行する。

## 6. リリース運用（Voice2QR 方式）

- バージョンの正は GitHub のタグ `vX.Y.Z`。`web/package.json` の `appVersion` は
  タグから `v` を除いたものと一致させ、タグを切る前に上げる。
- Pages ワークフローはタグ駆動（`v*` タグ＋手動実行）。
- 実機確認用は v0.1.0 番代、正式リリースは v1.0.0 番代。

## 7. v1 の対象外

- サーバへのアップロード、履歴保存、複数画像の一括変換（CLI の仕事）。
- 画像編集（トリミング、回転の手動調整、文字入れ）。EXIF 回転の吸収は行う。
- カラー変換（pic2color4px の領域）。
- プリンタへの直接接続（Web Bluetooth 等）。出力は共有／保存／ブラウザ印刷まで。

## 8. 実機確認項目

- スマホ写真（EXIF 回転あり）を取り込んで向きが正しいこと。
- 大きな原画（12MP 級）を原画サイズのまま変換する時間を実機で測ること。
  自動調整は候補ごとの全変換評価＋最大 10 パスの最適化であり、本プロジェクト
  最大の性能リスク。実用に耐えない場合は、実行前の確認や縮小提案を出す
  条件を v1 の要件に追加してから実装する。
- 共有シートから Phomemo アプリへ渡した 1-bit PNG がそのまま印刷できること。
- PWA をホーム画面に追加し、単独ウィンドウで起動すること。
- 他のアプリ（写真アプリ等）の共有メニューから本アプリへ画像を渡せること（Android）。
- iOS Safari で、写真をコピー→貼り付け受け箱をタップ→呼び出しメニューの
  「ペースト」で取り込めること（JPEG で置かれたコピーでも）。
- T02 / M02S 実機での刷り比べ（CLI の最終判定と共通）。

## 9. 色調整 UI（v0.2.0）

色調整の要件本体は `docs/adjustment-requirements.md` §7。ここでは
画面側の仕様だけを定める。

- 「色調整」欄を出力幅の選択の下に置く。ミキサー（標準／赤寄り／
  緑寄り）とトーンカーブ（ノーマル／明暗強調）はチップで単一選択
- **初期選択は warm（赤寄り）× contrast（明暗強調）**。印刷実験の
  結果による利用者決定（2026-11-16）。コアの省略時デフォルト
  （標準 × ノーマル）は変えず、画面は初期選択を常に明示的に渡す
- lift-blacks（黒を明るく）は選択肢に出さない（実験で不評のため）
- 局所コントラストは上級者設定の強さスライダ（0.0〜1.0、初期値
  0.0）だけで制御する。0 が OFF で、ON/OFF のチェックは置かない
  （強さと二重管理になるため）
- 結果メタ表示に、適用されたレシピ（ミキサー名 × カーブ名、局所
  コントラストが有効な場合はその値も）を出す。値は WASM の戻り値
  （実際に適用された値）を正とする
- 変換は WASM の `convert_rgba_adjusted` を使う。プリセット名の
  解決はコア側（名前表が正本）
