# 色調整 要件定義

pic2gray4px の変換前段に「色調整」を追加する要件。
対象はコア（ライブラリ）・CLI・Web の3面で、パラメタはコアに集約する。

## 1. 目的

現在の変換は、色→グレーの変換が固定の輝度式（Rec.709）で、
明暗の調整も均一なコントラスト係数が担っている。
そのため、色相だけが持つコントラスト（例：グリーンとオレンジは
輝度がほぼ同じで、グレーでは境界が消える）が入口で失われ、
写真の「色の落ち方」や「明暗の性格」を選ぶ手段がない。

色調整は次を提供する：

1. **チャンネルミキサー**：色→グレーの重みを選べる（色の落ち方）
2. **トーンカーブ**：明暗の性格を3種から選べる
3. **局所コントラスト**：質感と輪郭の分離を強められる（上級者向け）

ミキサーとトーンカーブの組み合わせ（3×3＝9通り）を候補として提示し、
最終的な良し悪しは人間の目と印刷結果で判断する。
数値指標による自動選択は、この層では行わない。

## 2. 動作例

### CLI

```
$ pic2gray4px photo.jpg out.png --width 576 \
    --mixer warm --tone-curve contrast --local-contrast 0.5
out.png (576x432, 1-bit grayscale PNG; mixer=warm (0.50, 0.35, 0.15);
tone-curve=contrast; local-contrast=0.50; contrast=1.00 auto; ...)
```

### Web

1. 写真を入れる
2. 色調整で「暖色重視」×「明暗強調」を選ぶ（初期値は 標準 × ノーマル）
3. 必要なら上級者設定で局所コントラストを上げる
4. 結果表示に、適用したミキサー／カーブ／局所コントラストの値が出る

## 3. 処理の流れ

色調整は変換パイプラインの前段に、次の順で入る：

```
RGBA → リサイズ → ミキサー（色→グレー） → トーンカーブ
     → 局所コントラスト → 従来の前処理と候補探索 → セル最適化 → 1-bit PNG
```

- ミキサーは現在の `fill_luminance` の固定重みを置き換える
- トーンカーブと局所コントラストは、グレー平面に対する処理
- 局所コントラストは「局所平均（ベース）」と「平均との差（ディテール）」に
  分け、ディテールの増幅率が偏差の大きさで変わる方式とする
  （大きなエッジでは増幅を抑え、ハロを出さない）。
  ぼかしの半径は出力幅から内部で決め、パラメタには出さない
- **基準画像**：色調整後のグレー平面を、後段の自動補正および
  出力品質評価の基準画像とする。元 RGBA から算出した Rec.709 輝度を
  評価基準として再利用しない。利用者が選んだ色調整を新たな目標画像
  として扱い、自動補正はその目標の再現のために働く
- 局所コントラストの増幅関数と半径の決定規則は、実装時に設計文書へ
  明文化する（CLI と WASM の結果一致を検証可能にするため）

## 4. パラメタ仕様（コア）

`ConversionOptions` への追加。コアは「RGBA ＋ パラメタ一式 → 結果」の
純粋な関数のままとし、CLI と Web は同じパラメタを渡す。
同一パラメタでは CLI と Web（WASM）の結果が一致すること（従来の契約）。

| パラメタ | 型 | 既定値 | 範囲 | 意味 |
|---|---|---|---|---|
| mixer | (f32, f32, f32) | (0.2126, 0.7152, 0.0722) | 各要素は有限数、−2.0〜2.0（案） | 色→グレーの重み (wR, wG, wB)。合計による正規化はしない |
| tone_curve | 列挙 | normal | normal / contrast / lift-blacks | グレー平面にかける単調カーブ |
| local_contrast | f32 | 0.0 | 0.0〜1.0 | 局所コントラストの強さ。0 で無効 |

- **新規パラメタはいずれも省略できる。省略時は標準が既定になる**
  （mixer = standard の重み、tone_curve = normal、local_contrast = 0）。
  既存の contrast / unsharp の省略（＝自動探索）とは意味が異なる。
  新規パラメタに自動探索はなく、省略は常に標準プリセットを指す
- 既定値の正本はコアに置く。CLI / Web は省略をそのままコアへ渡し、
  自分で既定値を埋めない（既定が面ごとにズレるのを防ぐ）
- 範囲外・非有限の値はエラーにする（既存の contrast / unsharp と同じ流儀）
- プリセットは「名前 → 重みの組」の表としてコアが持ち、コアが名前解決の
  関数を提供する。CLI / Web は名前を重みに解決してから渡す
  （プリセット定義の正本をコア1か所にするため）
- `ConversionResult` には適用した mixer / tone_curve / local_contrast を
  返す（既存の contrast / unsharp の適用値表示と同じ流儀）。
  CLI の出力行と Web の結果表示はそれを表示する
- ミキサーの出力（重み付き和）は 0〜1 にクランプしてから後段に渡す。
  負の重みや、合計が 1 を超える重みでは和が範囲を出るためである
- カスタム重みでは合計 1 を必須としない（合計 1 はプリセット側の約束）
- 既定の重み（standard）を指定した場合は、現行 `fill_luminance` と
  同じ演算順序を維持し、浮動小数点の丸めまで含めて従来と同一の
  グレー値を得ること（バイト一致の前提）
- **既定値の組み合わせでは、従来の変換結果とバイト一致すること**
  （mixer 既定＝現行の重み、tone_curve=normal は恒等、
  local_contrast=0 は無効、として後方互換を保つ）

## 5. プリセット定義（叩き台）

数値はいずれも初期候補であり、§8 の実験（実写真＋印刷）で調整して確定する。

### ミキサー（重みの合計は 1 とする）

重みの合計を1にすると無彩色（R=G=B）の明度が保持され、
有彩色のグレー化における明度配分のみ変更される。

| 名前 | 役割 | 重み (wR, wG, wB) |
|---|---|---|
| standard | 汎用（現行の Rec.709） | (0.2126, 0.7152, 0.0722) |
| warm | 暖色重視：赤・オレンジ・肌が明るく落ちる | (0.50, 0.35, 0.15) |
| green | 緑色重視：赤を沈め、緑との分離を強める | (0.15, 0.65, 0.20) |

### トーンカーブ（アンカー点で定義する）

カーブは単調非減少とする。アンカー点は (入力, 出力) の組（いずれも 0〜1）。
アンカー点の間は区分線形補間とする（2026-11-16 レビューで確定：
単調性を保証しやすく、再現性が高い。滑らかな補間への変更は、
印刷実験の結果を見てから検討する）。

| 名前 | 性格 | アンカー点 |
|---|---|---|
| normal | 素直（恒等） | (0, 0) (0.5, 0.5) (1, 1) |
| contrast | 明暗強調：影とハイライトを締める S 字 | (0, 0) (0.25, 0.16) (0.5, 0.5) (0.75, 0.84) (1, 1) |
| lift-blacks | 黒を明るく：黒の床を持ち上げ、淡くする | (0, 0.14) (0.25, 0.34) (0.5, 0.56) (0.75, 0.79) (1, 0.96) |

## 6. CLI 表面

| オプション | 値 | 備考 |
|---|---|---|
| --mixer | standard / warm / green | 名前で指定 |
| --mixer-weights | "R,G,B" | 重みの直接指定（調整実験用）。--mixer と同時指定はエラー |
| --tone-curve | normal / contrast / lift-blacks | |
| --local-contrast | 0.0〜1.0 の数値 | |

## 7. Web 表面

- 色調整の選択欄を設ける：ミキサー3種 × トーンカーブ2種
  （normal / contrast）をそれぞれ選ぶ、3×2 の選択肢とする。
  初期選択は **warm × contrast**（実験の結果による、2026-11-16 決定）。
  lift-blacks は選択肢に出さない
- コアの省略時デフォルト（standard × normal、バイト一致の前提）は
  変更しない。Web は初期選択を常に明示的に渡す
- 局所コントラストは選択欄に ON/OFF を置く（初期値 OFF）。
  ON の強さは当面 0.5 とし、上級者設定で 0.0〜1.0 を変更できる
- 結果表示に適用レシピ（ミキサー名／カーブ名／局所コントラスト値）を出す
- 詳細な画面仕様は `docs/web-requirements.md` 側に追記する

## 8. 実験と調整

重み・カーブ・局所コントラストの効きは、画面ではなく印刷で判定する。

1. 試験写真の顔ぶれ：人物（肌）、風景（空と緑）、暖色の被写体、
   質感のある物、イラスト・線画
2. 9通り＋局所コントラスト ON/OFF を印刷し、人間の目で比較する。
   出力幅（384 / 576）まで含めた全組み合わせは1画像あたり36出力に
   なるため、まず同一幅で9通りを比較して候補を絞り、絞った候補を
   幅 576 で再試験する進め方でもよい
3. 結果を見て重みとアンカー点を動かし、プリセット値として確定する
4. 局所コントラストは、効果が確認できれば既定値への採用を検討する。
   ただし今回のバージョンでは既定値 0.0 を維持する。将来既定値を
   変更する場合は、§4 のバイト一致要求への影響を評価して別途決定する

### 実験結果（2026-11-16、第一報）

試験画像5種（AI 生成の写真4点＋描画イラスト1点、リポジトリの
`adjustment-experiment/` に収録）で第一段の比較を行った：

- 人物・紅葉とも **warm × contrast** が好評
- **lift-blacks は全画像で不評**（「汚い」）。平面の値域が
  [0.14, 0.96] に圧縮され、真の黒が消えて全体が中灰のディザに
  なることが原因と考えられる。利用者向けプリセットからは
  外す方向とし、最終判断は残り画像の評価と合わせて確定する
  （カーブの仕組み自体はコアに残る）
- 風景・質感・イラストの評価と、実印刷での確認は継続する

### 実験結果（2026-11-16、第二報）

- 風景（山と川）・イラスト・マフラー（人物）でも **contrast が
  直感的に良い／綺麗** と評価された
- 現時点で contrast は、評価された全ての被写体で支持されている。
  ミキサーは被写体依存（暖色系では warm）だが、カーブについては
  contrast が共通の勝ち筋になっている
- 質感（ニット）の単独評価と、実印刷での確認は継続する

## 9. 検証条件

- 既定パラメタで従来結果とバイト一致する（ゴールデンテスト）
- 同一パラメタで CLI と Web の結果（ピクセル＋PNG）が一致する
- 合計 1 の重みでは、無彩色のグレー値が standard と一致する
- トーンカーブが単調非減少である
- 範囲外パラメタがエラーになる
- ミキサーの出力が 0〜1 にクランプされる（範囲外の重みでも、
  後段への入力が範囲内に収まる）

## 10. 決定事項と未決事項

決定（2026-11-16 レビュー）：

1. 基準画像は色調整後のグレー平面とする（§3）。自動調整の探索対象は
   従来通り contrast / unsharp のみとし、ミキサーとカーブは探索の
   前段で確定する。ただし、どの程度の自動補正を色調整と併用するかは
   §8 の実験で確定する
2. アンシャープと局所コントラストは当面併存させる。担当範囲の整理：
   アンシャープは細い線・文字・小さな輪郭、局所コントラストは
   物体表面の陰影と比較的大きな明暗差。局所コントラストの既定値は
   0.0 とし、実験で個別に ON/OFF と組み合わせを比較する

未決：

3. 利用者向けの表示名（ミキサー／カーブの名前）の最終決定
