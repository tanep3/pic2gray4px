# セル間白点交換（タルモン方式）設計

要件は `docs/exchange-requirements.md`。本書は実装の置き方と、
計測で踏んだ落とし穴の記録である。

## 1. 置き場所

交換は `src/optimizer.rs` の `optimize_impl` の最終段として実装する。
新しいモジュールは作らない（配置最適化と残差・カーネルを共有するため）。

```
個数決定 counts() ── 拡散あり/なし（従来通り）
        ↓
配置最適化（個数固定、従来通り）
        ↓
交換ラウンド × N（round ごとに方向を反転）
    exchange_sweep(): 隣接ペアで白点1個を交換し、合同コストが下がれば確定
    placement_polish(): 配置のみの磨き直し（収束まで）
```

`optimize` / `optimize_f64` の両入口に `exchange: usize` 引数を追加し、
`optimize_gray8` 系（参照経路）は 0 を渡して従来と完全一致を保つ。

## 2. 交換の評価式

配置最適化のコスト増分は `2·δᵀR + δᵀKδ`（R は残差＝誤差のぼかし、
K は 9×9 知覚カーネル）。交換では2セル分の δ（最大8画素）を合同で
組み立て、同じ式で評価する。確定したら残差を δ の分だけ増分更新する
（配置段と同じ更新規則）。ペア列挙は直交隣接のみ、全パターンペアを
数える（個数 k のセルは C(4,k) 通り）。

可否条件：移動後の両セルの個数が `[required_white の下限, 4]` に
収まること。パディングに掛かるセルの必須白を壊さないため。

## 3. 目的関数の注意（計測で踏んだ穴）

配置コストが厳密に最小化しているのは **E = ⟨e, K⊛e⟩**（誤差と
そのぼかしの内積）であって、‖K⊛e‖²（残差の二乗和）ではない。
比較実験の初回は二乗和で測り、「質感画像で交換が悪化する」という
偽の結果を得た。正しい物差し（E）では全画像で改善する。

ただし E は中域周波数寄りの物差しで、低周波の階調偏り（グラデーション
の縞）や平坦部の斑点は目ほどには拾わない。拡散の要否が被写体で
割れるのはこのためで、最終判定は数値でなく目視と印刷に置く
（要件 §4 のモード分けはこの目視判定が根拠）。

## 4. ラウンド数の測定（モード既定 = 3 の根拠）

幅384・拡散あり・warm×contrast 固定、内部目的関数 E の推移：

| 画像 | 1ラウンド | 2ラウンド | 3ラウンド |
|---|---|---|---|
| 人物 | 6,149 | 6,107 | 6,092 |
| 風景 | 2,427 | 2,405 | 2,397 |
| イラスト | 3,402 | 3,375 | 3,364 |

2ラウンドで大半を取り、3ラウンド目も一貫して小さい改善がある。
判定に使った比較シートが3ラウンド生成だったこともあり、
「判定した物と同じ物を出す」ため既定は 3 とした。

## 5. 自動探索との接続

`convert_with_options` の候補ループは交換 0 で回し、勝者の
(factor, amount) が決まってから、その候補面を再構築して交換付きで
再実行する（前処理は決定的なので再構築は同一面になる）。
探索中のスコアは交換なし出力に対するもので、結果メタに返る
適用値（contrast / unsharp）は勝者のもの、交換ラウンド数は
オプションの指定値がそのまま返る。

## 6. モード解決の置き場所

モード名→（拡散, 交換）の表はコア（`pic2gray4px::mode_preset`）が
正本。CLI の `--mode` と WASM の `mode_name` はどちらもこの表を引く。
Web の TS 側に表の写しは置かない（表示名だけを持つ）。

## 7. バイト一致の担保

- 交換 0：ゴールデンテスト全通過＋従来バイナリとの出力 SHA-256 一致を
  実測（人物・風景、幅384・調整ピン留め）。
- 製品実装＝実験実装の照合：実験ハーネスのピン留め条件で、
  製品バイナリの交換出力が実験出力とバイト一致することを実測
  （人物 B・風景 B・イラスト B/D）。
- 不変量テスト：交換の有無で白点総数が一致すること
  （`exchange_preserves_white_total_and_changes_pixels`）。
